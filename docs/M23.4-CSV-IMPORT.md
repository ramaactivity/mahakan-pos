# M23.4 CSV Import / Export — Operational Guide

Owner-facing guide untuk workflow data inventory via CSV. Standard format,
roundtrip aman: template → fill → dry-run → apply → export untuk re-edit.

---

## 1. Workflow Singkat

```
┌─────────────────────────┐
│  npm run inventory:     │ → data/templates/01-...csv ... 05-...csv
│  template               │   (5 CSV blank dengan 1 example row)
└─────────────────────────┘
            │
            ▼  Owner kasih file ke staff (zip / WA / email)
┌─────────────────────────┐
│  Staff isi data di      │ → Hapus baris EXAMPLE_DELETE_ME
│  Excel / Google Sheets  │ → Isi data sesuai format
└─────────────────────────┘
            │
            ▼  Staff balikin file → Owner save ke data/source-spreadsheets/
┌─────────────────────────┐
│  npm run inventory:     │ → Parse + validasi + reconcile vs DB existing
│  import                 │ → Print report (NEW/UPDATE/SKIP/ERROR per row)
│  (DRY-RUN, no writes)   │ → JSON sidecar di data/exports/import-<id>/
└─────────────────────────┘
            │
            ▼  Review report → fix CSV → re-run dry-run sampai bersih
┌─────────────────────────┐
│  npm run inventory:     │ → Atomic write ke DB
│  import -- --apply      │ → Cascade cost otomatis fire untuk preps
│                         │ → Audit log: inventory.import.run + per-row
└─────────────────────────┘
            │
            ▼  Bulanan / saat update harga
┌─────────────────────────┐
│  npm run inventory:     │ → Dump current DB ke data/exports/<ts>/
│  export                 │ → Edit hasil → re-import (idempotent)
└─────────────────────────┘
```

## 2. Format File

5 file long-format CSV. Tiap baris = 1 entitas atau 1 ingredient line.
Parent direferensikan via **name** (case-insensitive trim).

### 2.1 `01-ingredients.csv` — Bahan Baku Atomic

```csv
name,unit,cost_per_unit,initial_stock,reorder_threshold,notes
Ayam Fillet,gr,57000,1000,200,
Beans Houseblend,gr,165000,1000,500,Premium roast
Susu Omela,ml,16,1000,200,
```

| Kolom | Tipe | Wajib | Catatan |
|---|---|---|---|
| `name` | text (max 80) | ya | Unique per outlet. Case-insensitive. Whitespace di-trim. |
| `unit` | text (max 16) | ya | `gr`, `ml`, `pcs`, `slice`, dst. |
| `cost_per_unit` | integer rupiah | ya | Per 1 unit (1g, 1ml, dst). Format `Rp 57.000` juga diterima (legacy). |
| `initial_stock` | integer ≥ 0 | tidak (default 0) | **HANYA dipakai saat NEW** — di-IGNORE saat UPDATE (avoid wipe receivings). |
| `reorder_threshold` | integer ≥ 0 atau kosong | tidak | Kosong = no alert. 0 = always alert. |
| `notes` | text (max 500) | tidak | Free text. Escape comma dengan `"..."` (RFC 4180). |

### 2.2 `02-preparations.csv` — Sub-Recipe (Computed Cost)

```csv
name,unit,yield,waste_factor_pct,notes
Prep - Espresso HB,ml,45,10,
Prep - Sambal Matah,gr,366,10,
Prep - Saus Coklat,gr,150,10,
```

| Kolom | Tipe | Wajib | Catatan |
|---|---|---|---|
| `name` | text | ya | Unique. Tidak boleh bentrok dengan name di file 01. |
| `unit` | text | ya | Unit yield (mis. `ml` untuk espresso). |
| `yield` | integer > 0 | ya | Berapa unit dihasilkan dari 1× resep. |
| `waste_factor_pct` | 0-200 | ya | Q Factor (typical 10% untuk prep). |
| `notes` | text | tidak | |

Cost otomatis di-compute oleh engine dari resep di file 03.

### 2.3 `03-preparation-lines.csv` — Bahan dalam Preparation

```csv
prep_name,ingredient_name,qty
Prep - Espresso HB,Beans Houseblend,16
Prep - Espresso HB,Refill Galon Cleo,110
Prep - Sambal Matah,Bawang Merah,75
Prep - Sambal Matah,Sereh,20
```

| Kolom | Tipe | Wajib | Catatan |
|---|---|---|---|
| `prep_name` | text | ya | Lookup ke file 02 (atau preparation existing di DB). |
| `ingredient_name` | text | ya | Lookup ke file 01 (atomic) ATAU 02 (nested prep). Auto-detect by name. |
| `qty` | integer > 0 | ya | Jumlah dalam unit dari `ingredient_name`. |

**Aturan**:
- Duplikat `(prep_name, ingredient_name)` di file → ERROR.
- Ingredient name yg gak match di 01/02/DB → ERROR.
- Cycle (Prep-A → Prep-B → Prep-A) → ERROR (pre-flight check).

### 2.4 `04-menu-recipes.csv` — Recipe Menu (Header)

```csv
menu_name,variant,waste_factor_pct,notes
Iced Americano,iced,30,
Hot Americano,hot,30,
French Fries,,30,
Cappuccino,iced,30,
Cappuccino,hot,30,
```

| Kolom | Tipe | Wajib | Catatan |
|---|---|---|---|
| `menu_name` | text | ya | Lookup ke `menu_items.name` (outlet-scoped, case-insensitive). **Tidak ditemukan → ERROR** (engine TIDAK auto-create menu). |
| `variant` | `hot` / `iced` / kosong | tidak | Kosong = fixed-price menu. |
| `waste_factor_pct` | 0-200 | ya | Q Factor menu (typical 30%). |
| `notes` | text | tidak | |

### 2.5 `05-menu-recipe-lines.csv` — Bahan dalam Menu Recipe

```csv
menu_name,variant,ingredient_name,qty
Iced Americano,iced,Prep - Espresso HB,35
Iced Americano,iced,Refill Galon Cleo,140
Iced Americano,iced,Cup 12 oz,1
Hot Americano,hot,Prep - Espresso HB,35
French Fries,,French Fries,140
French Fries,,Paper Bag,1
```

| Kolom | Tipe | Wajib | Catatan |
|---|---|---|---|
| `menu_name` + `variant` | joint key | ya | Lookup ke recipe yg di-define di file 04. |
| `ingredient_name` | text | ya | Lookup ke 01 (atomic) atau 02 (prep). |
| `qty` | integer > 0 | ya | |

**REPLACE semantics**: kalau recipe sudah ada, lines lama di-DELETE + lines baru di-INSERT. Kalau gak mau ubah, jangan include di file 05 (recipe-nya tetap di file 04 sebagai SKIP).

## 3. Commands

### 3.1 Generate template

```bash
npm run inventory:template               # write 5 file (refuse-if-exists)
npm run inventory:template -- --force    # overwrite
```

Files ditulis ke `data/templates/`. Path ini gitignored — aman untuk
edit-in-place.

### 3.2 Export current DB state

```bash
npm run inventory:export                 # auto-detect outlet
npm run inventory:export -- --outlet <uuid>   # multi-outlet override
```

Hasil di `data/exports/<YYYYMMDD-HHmmss>/01-...csv ... 05-...csv`. Run
multiple times → multiple snapshot dirs (no overwrite).

Use case:
- Backup snapshot sebelum update massal
- Export → edit di Excel → re-import (kalau gak hafal nama-nama bahan)
- Verify roundtrip: import → export → diff = empty (modulo timestamps)

### 3.3 Import CSV (dry-run + apply)

```bash
# Default = dry-run (no writes)
npm run inventory:import
npm run inventory:import -- --source <path>

# Apply (atomic; refuses if any error)
npm run inventory:import -- --apply
npm run inventory:import -- --source <path> --apply
```

**Default source**: `data/source-spreadsheets/`. Kalau Owner pakai hasil
export untuk re-edit, set `--source data/exports/<ts>`.

**Output**:
- Per-row table: `[NEW]`, `[UPDATE]`, `[SKIP]`, `[ERROR]` dengan detail
- Summary counts per file
- JSON sidecar di `data/exports/import-<runId>/import-report.json`
- Apply mode: 1 audit event `inventory.import.run` di-emit dengan
  `metadata.outletId` + `entityId=runId`

**Atomic guarantees**:
- Single `db.transaction` wrap semua 5 file
- Apply mode refuses kalau ada errors → rollback, no partial commits
- Cascade cost otomatis fire untuk preps yang berubah

## 4. Reconciliation Rules

| Lookup | Kriteria |
|---|---|
| Ingredient/Preparation by name | Trim + lowercase; outlet-scoped |
| Menu item by name | Trim + lowercase; outlet-scoped |
| Existing recipe untuk prep | `recipes.ingredient_id = <prep.id>` |
| Existing recipe untuk menu | `(menu_item_id, variant)` joint |

| Diff Action | Trigger |
|---|---|
| `NEW` | Tidak ada di DB |
| `UPDATE` | Sudah ada + ada field berubah |
| `SKIP` | Sudah ada + tidak ada perubahan |
| `ERROR` | Validasi gagal (cycle, lookup miss, dup, dst) |

**Cost change → cascade**: Kalau `cost_per_unit` atomic ingredient berubah,
engine otomatis recompute cost semua preparation yang transitively pakai
ingredient itu (via `cascadeCostUpdate` dari M23.2).

## 5. Edge Cases & Error Resolution

| Error | Penyebab | Fix |
|---|---|---|
| `name kosong` | Cell `name` empty di non-empty row | Hapus row atau isi name |
| `cost_per_unit bukan angka valid: "XYZ"` | Bad number format | Pakai integer rupiah (`57000`) atau `Rp 57.000` |
| `name duplikat dengan baris N` | 2 row dengan `name` sama (case-insensitive) di file 01/02 | Hapus salah satu |
| `(prep_name, ingredient_name) duplikat` | 2 line untuk pasangan sama di file 03 | Sum manual atau hapus |
| `prep_name tidak ditemukan` | File 03 reference prep yg gak ada di 02/DB | Tambah ke file 02 atau cek typo |
| `ingredient_name tidak ditemukan` | Ingredient gak ada di 01/02/DB | Tambah ke file 01 |
| `menu_name tidak ditemukan di outlet` | Menu belum dibuat | Tambah via Admin UI dulu, baru re-import |
| `akan membentuk siklus dependensi` | Prep-A → Prep-B → Prep-A | Refactor recipe untuk break cycle |
| `name bentrok dengan existing preparation` | File 01 punya name yg sudah ada sebagai prep | Pilih name beda atau hapus prep dulu |
| `variant harus 'hot', 'iced', atau kosong` | Bad variant value | Normalize ke `hot`/`iced`/kosong |

## 6. Audit Trail

Setiap import run emit serangkaian audit events:

- `inventory.ingredient.create` per ingredient NEW (existing dari M22.2)
- `inventory.ingredient.update` per ingredient UPDATE
- `inventory.preparation.create` per prep NEW (M23.2)
- `inventory.preparation.update` per prep UPDATE
- `inventory.preparation.recompute` per cascade-affected prep (auto dari M23.2)
- `inventory.cost.cascade` per cascade run (auto dari M23.2)
- `inventory.recipe.create`/`inventory.recipe.update` per menu recipe
- **`inventory.import.run`** — 1 final summary event dengan:
  - `entityId`: runId (UUID)
  - `payload.summary`: human-readable count
  - `payload.after`: full counts + source path
  - `metadata.outletId`: target outlet
  - `metadata.actorRole`: `"import-cli"` (vs `"owner"`/`"manager"` dari UI)

Query audit log via Drizzle Studio atau `SELECT * FROM audit_logs WHERE event_type LIKE 'inventory.%' AND metadata->>'outletId' = '...'`.

## 7. Outlet Resolution

Default: auto-detect single outlet. Failure modes:
- 0 outlet di DB → fail (jalanin `npm run db:seed` dulu)
- >1 outlet → fail dengan list, pakai `--outlet <uuid>`

Mahakan currently single-outlet, jadi auto-detect always works.

## 8. Actor Attribution (Audit)

Engine baca `process.env.SEED_OWNER_EMAIL` (sama seperti `db:seed`) untuk
lookup user.id sebagai actor di audit log. Kalau env kosong, audit
`userId` = null (tetap valid, cuma kurang traceable).

## 9. Common Workflows

### 9.1 First-time bulk import (kafe baru)

```bash
npm run inventory:template
# Owner edit data/templates/*.csv (atau forward ke staff)
mv data/templates/*.csv data/source-spreadsheets/
npm run inventory:import           # dry-run sampai bersih
npm run inventory:import -- --apply
```

### 9.2 Update massal harga supplier (bulanan)

```bash
npm run inventory:export                                    # snapshot current
# Edit data/exports/<ts>/01-ingredients.csv (update cost_per_unit)
npm run inventory:import -- --source data/exports/<ts>     # dry-run
npm run inventory:import -- --source data/exports/<ts> --apply
# Verify cascade: cek audit_logs untuk inventory.cost.cascade events
```

### 9.3 Add new menu R&D (1 menu baru)

1. Buat menu_item via Admin UI (set name + price + category)
2. Append baris di file 04 + 05 dengan recipe
3. `npm run inventory:import -- --apply`

### 9.4 Audit + rollback

Kalau apply mengakibatkan masalah:
1. Cek `data/exports/import-<runId>/import-report.json` untuk runId
2. Restore dari Neon backup (snapshot pre-run via GHA workflow)
3. Re-run import dengan CSV yang sudah dibetulkan

## 10. Limitations / Out-of-Scope

| Limitation | Reason |
|---|---|
| Tidak bisa create menu_item via importer | Pricing + category butuh keputusan manual |
| `initial_stock` di-IGNORE saat UPDATE | Avoid wipe receivings yang sudah masuk |
| Cost change tidak bikin `inventory_movement` | Movement = perubahan stok, bukan harga |
| Multi-outlet butuh `--outlet <uuid>` | Single-outlet auto-detect default |
| xlsx multi-sheet template | CSV cukup; xlsx dep heavy (M23.6+ kalau perlu) |
| UI download button untuk template | M23.5+ kalau Owner sering update |
| Schedule/cron auto-import | Owner-triggered manual sesuai design |

## 11. Troubleshooting

**`DATABASE_URL not set in .env.local`**: file `.env.local` gak ada atau
`DATABASE_URL` belum di-set. Copy dari `.env.local.example`.

**`Tidak ada outlet di DB`**: Database fresh — jalanin `npm run db:seed`
dulu untuk bikin outlet + Owner user.

**`Multiple outlets ditemukan`**: Add `--outlet <uuid>` flag.

**`Cannot find module 'server-only'`**: Bug regresi — semua module yang
di-import dari script CLI tidak boleh punya `import "server-only"`. Cek
import chain dengan stack trace; remove server-only line dari module
yang offending.

**Import lambat**: Mahakan dataset (~200 rows total) selesai dalam ~5-10
detik. Kalau lebih lama, Neon free-tier cold-start bisa add 2-3 detik
overhead pada koneksi pertama.
